# v0.1.1 验证说明

版本：`v0.1.1`，实验性预发布。

## 自动化测试范围

`npm test` 检查协议桥、历史同步、输入保护、管理 CLI 和运行时引导。`python3 installer/remote.test.py` 单独检查远端安装器。

| 范围 | 检查内容 |
| --- | --- |
| 聊天协议 | ACP 转换、消息和进度事件、审批映射、明确拒绝未实现 API |
| 历史同步 | 增量读取、ID 对齐、重复消息处理、部分与损坏文件恢复 |
| tmux 输入 | 进程身份、前台状态、草稿保护、多行与长粘贴校验 |
| 安装生命周期 | 安装、只读诊断、维护屏障、升级、卸载及配置归属 |
| 私有运行时 | 官方来源、摘要校验、安全解包、缓存复用与失败路径 |
| 分发 | 安装包文件、CLI 入口、skill 安装和依赖布局 |

测试使用隔离临时数据，不发送付费模型请求。部分集成测试需要原版 Codex CLI；程序缺失时会跳过，跳过不计为集成验证通过。通过、失败和跳过数量以该版本实际测试输出为准。

仓库附带尚未启用的 GitHub Actions 模板，包含 Node.js 22/24、Linux/macOS。模板不代表该矩阵已经运行。

## 分发与校验

分发文件为 GitHub Release 中的 `cursor-codex-bridge-0.1.1.tgz`，由 `npm pack` 生成；未向 npm 发布同名包。安装包的校验摘要在发布后补充，以对应最终上传的文件。下载后应将本地 SHA-256 与该版本发布说明中的摘要比对。

公网下载、`npx` 执行和运行时二进制检查需要在发布后针对最终附件验证；源码测试不能替代这些检查。

## 兼容边界

安装和诊断通过不能证明任意 Codex App、Cursor Agent、终端主题、模型格式或操作系统组合均可用。tmux 代发依赖可识别的输入框、原进程身份和空闲状态；无法确认时拒绝提交并保留草稿。详见 [故障排查](troubleshooting.md)。

使用前应在自己的环境验收需要的工作流。自动化测试不替代原生 App、SSH、Cursor 登录和 tmux 的端到端验证。

# v0.1.6 验证范围

此版本修复共享 tmux 发送路径对短多行消息的六行限制。原文经一次 bracketed paste 进入原输入框，在 pane 专属输入租约下核验全文。短暂输入的随机校验标记帮助识别连续空行；确认全文后精确删除标记，再提交原文。提交内容不合并段落、不添加填充字符，保留首尾换行。已有输入锁、`pipe-pane`、草稿及未知界面继续阻止接管。

原生提交恢复使用显式来源凭据，额外绑定原 `clientId`、模型、原始输入哈希和来源映射。沿用既有来源历史的 LF 与首尾空白规范化匹配，同时单独校验原生输入的原始哈希，恢复时保留原消息内容。该历史匹配规则不用于放宽新多行草稿的原文核验。

已完成的隔离验证：

| 范围 | 结果 |
| --- | --- |
| 来源凭据、恢复与真实桥 RPC 隔离测试 | 38 项通过 |
| 原生提交恢复 | 原 `clientId`、轮次和消息 ID、原始输入及模型保留；来源在断线期间或首次读取时完成，均收尾同一原生轮次 |
| 错误证据 | client、模型、来源、进程、哈希或队列冲突会阻止恢复；不重试、不取消、不启动另一 Agent |
| 恢复后新增队列 | 完成与断开均保留原始用户输入及归属；重启遇到未处理队列时拒绝接管，不重发原请求 |
| 原文核验 | 连续空行、首尾换行、缩进、中文和 emoji；拒绝无法逐字符核验的组合字符光标状态及可被 Cursor 展开替换的粘贴引用 |
| 真实 Linux / tmux 输入租约 | 20 项通过；原键盘与普通 send-keys 被阻止，覆盖租约到期、进程退出、迟到回执、替代 pipe、界面重绘及 800 次独立导航 |
| 真实 Cursor 草稿，无模型请求 | 17 行 / 466 UTF-16 单位与 7 行 / 800 单位均完成全文核验、删除标记、清空自建测试草稿；来源历史未变。优化后 800 单位测试约 125 秒，低于 300 秒截止 |
| 外部观察兼容性 | 原有严格外部观察凭据不接受原生 client；旧忙碌画面不创建重复轮次 |

来源恢复测试使用隔离数据和终端替身；输入租约测试使用独立 tmux，真实 Cursor 草稿测试只操作自建测试窗口。以上均不发送模型请求。完整测试套件、实际部署和真实多行消息往返另外记录，不能用本表替代端到端验收；发布验收见 [v0.1.6 release notes](https://github.com/KatarinaYuan/cursor-codex-bridge/releases/tag/v0.1.6)。普通安装器继续拒绝忙碌升级。

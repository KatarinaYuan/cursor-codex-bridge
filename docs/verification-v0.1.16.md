# v0.1.16 验证范围

本版处理没有来源归属凭据的旧原生显示阻塞后续同步的情况。旧输入与正式来源正文可能不同，不能把它们宽松匹配成同一提交。修复把显示收尾、正式来源导入和最新来源观察分别验证；保留原始输入、客户端消息、Cursor 进程、模型及草稿。

## 显示收尾的证据边界

候选旧显示必须结构完整，没有既有来源归属、冲突的运行轮次、排队请求或未解决的提交草稿。显示收尾还需核对以下独立证据：

- 同一原会话、工作目录、tmux pane、Cursor 进程及启动时间。
- 旧显示之前已有映射、且明确完成的正式来源锚点。
- 原生开始所在分钟起的两分钟窗口内，存在近邻且明确完成的稳定来源；中间来源前缀均有明确结束记录。
- 最新请求有唯一稳定封套，位于上述来源之后，时间戳严格更晚。
- 新鲜终端画面对应最新来源的受支持忙碌状态、完整提问框，或适用的完整结束与空闲画面；核对前后原进程绑定未变。

正文相似度不构成来源归属。只把旧显示记为已中断，保留原生轮次、消息、客户端消息 ID 和原始正文，并保存显示收尾凭据。正式完成来源独立导入，不为旧显示追加来源映射或改报成功。相同客户端与原始输入的重试应返回旧显示；输入不同或凭据不完整时拒绝，不能成为新粘贴或模型请求。

最新未完成来源由自己的外部观察继续跟踪。历史同步须排除没有明确完成证据的最新尾部，即使解析器暂将其状态写为 `completed`。检查应支持重复扫描和桥重启，同时保留原任务、模型及私人 CLI 草稿。

长回复可能把最新用户框滚出默认 500 行。仅在短捕获没有用户框、且画面状态受支持时，显示收尾会只读重采一次最多 10,000 行的完整画面；外部观察附着还要求最新来源明确未结束、尚未观察且终端忙碌或等待答题。深捕获仍须实际包含匹配用户框，不从 transcript 拼造画面或放宽正文匹配；来源、进程或验证状态变化时放弃本次观察。该操作不滚动终端、不改配置、不发送按键、不接触草稿。

## 回归场景与实际验收计划

以下为本版需要验证的场景，不代表已经通过：

- 原生输入与近邻正式来源正文不同，证据完整时只中断旧显示，独立导入完整回复，并继续观察真实后续任务。
- 来源前缀、锚点、提交时间窗口、客户端 ID、模型、进程绑定或最新画面缺失或冲突时拒绝处理。
- 扫描发生在实时观察附着之前时，未结束尾部保持未完成；明确结束后只发布一次完成。
- 最新用户框超出短捕获时，从有上限的只读完整画面恢复；不支持的画面、已经结束的来源或已有待处理提交不触发外部附着回溯。
- 收尾持久化前后来源或进程变化、存储失败、重复扫描和重启不丢原文、不误认来源、不重复发送。
- 原生聊天显示完整正式回复和真实最新请求，旧预览不再长期运行；若最新任务仍忙碌或等待用户，保留真实状态。
- 实际部署逐文件核对冻结包与运行版本，核对原 Cursor 进程和模型；不向业务会话发送测试请求，不修改草稿或替用户回答。

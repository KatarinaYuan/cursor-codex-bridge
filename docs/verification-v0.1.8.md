# v0.1.8 验证范围

此版本针对短消息粘贴后误报无法核验的问题：中英文混排和尾部换行可能让 Cursor 的输入布局比桥按终端显示宽度预测的多一行，完整草稿因此超出六行可见区域。修复在粘贴前按更保守的输入布局规划临时列宽，并继续核验完整草稿，而不是仅凭可见末尾提交。

消息原文、空行及首尾换行必须保留。只在原进程、模型、来源历史和完整草稿均通过校验后提交一次 Enter；不匹配或布局无法确认时保留草稿，拒绝发送。已有失败草稿不会因升级自动提交。

本版验证分别检查输入布局回归、临时窗口恢复、草稿原文一致性、失败时拒绝发送，以及官方 v0.1.7 安装 skill 的安全升级。旧 skill 的两个官方文件均一致时，安装器保留完整备份再原子替换；定制内容、额外文件和符号链接仍拒绝覆盖。

自动化测试与真实部署验收的结果见 [v0.1.8 release notes](https://github.com/KatarinaYuan/cursor-codex-bridge/releases/tag/v0.1.8)。真实模型往返需要单独检查原始提交文本、来源回复、原生完成状态和模型身份；安装或诊断通过不能代替这一验收。

临时扩宽仍要求独占、未缩放且所需列宽不超过 1007 的 tmux 窗口。短消息的完整内容必须能由受支持的输入布局核验；未知界面、其他进程修改草稿或不满足恢复凭据时仍会拒绝代发。超过 800 个 UTF-16 字符的折叠粘贴和超过六个显式文本行的逐页核验继续沿用既有保护。原生来源身份修复的历史范围见 [v0.1.7 验证说明](verification-v0.1.7.md)。

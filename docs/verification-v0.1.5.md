# v0.1.5 验证范围

此版本修复外部 tmux 观察在来源已完成后重复创建运行轮次、导致原生聊天一直显示 `thinking` 的问题。新观察以 Cursor 来源轮次 ID 为准，并持久化来源轮次与原生轮次的对应凭据，以便桥重新连接后继续观察原任务或读取其正式完成记录；恢复过程不重发提示词。

验证须覆盖：已完成历史与终端残留忙碌画面不会产生重复轮次；新的活动来源能被观察；存在有效凭据时，运行中与已完成任务分别恢复到正确状态；无效或不匹配凭据不会被用于操作其他轮次。旧版缺少凭据的悬空记录需要单独诊断和迁移，不能把该预防机制等同于自动清理。

安装器保留空闲准入要求，不提供强制升级活跃手工部署的通用功能。安装 skill 固定到 `v0.1.5`；未修改官方 `v0.1.1` 至 `v0.1.4` 的两文件 skill 可备份升级，原有自定义内容、额外文件、符号链接保护与失败回滚保持生效。官方 `v0.1.4` 内容以固定测试夹具保存，测试不依赖 Git 或网络。

完整 Node 测试：364 项通过，0 失败、0 跳过，其中包括 66 项安装器测试。观察器定向复核覆盖 98 项测试，包含通过实际 RPC 启动隔离桥进程的重启与恢复场景：初次捕获期间来源完成、部分回复尚未结束、旧轮次结束后相同提示词的新来源、优雅关闭与跨进程恢复，以及来源或原进程身份不匹配时拒绝恢复。安装 skill 通过系统 `quick_validate.py` 校验。离线测试不发送付费模型请求。

本文记录可重复的离线验证范围；真实开发机部署和模型消息的验收结果单独记入对应 Release 说明。实机验收分别检查运行包校验、Codex 原生 Recents 列表、保留 Cursor 模型的实发回复和原会话进程及草稿保持情况。历史 Recents 验证范围见 [v0.1.4 验证说明](verification-v0.1.4.md)，长消息实发范围见 [v0.1.3 验证说明](verification-v0.1.3.md)。

公开测试使用虚构会话和临时目录。真实机器、账号、SSH 别名、来源会话、聊天内容和窗口画面均不随仓库或安装包发布。

# v0.1.11 验证范围

本版处理已有失败草稿在 App 编辑重发时的一种拒绝：App 会重新上传同一附件，新的 UUID 路径与原草稿不同，因此严格文本匹配会报告输入框仍有草稿。v0.1.10 的只读多行扫描修复仍保留；本版不放宽普通草稿或未知提交结果的保护。

路径归一只适用于已经存在严格失败草稿恢复凭据、且使用官方单附件包装的显式重试。除了附件路径中的 UUID 变化，其余全文必须逐字节一致，包括业务原文、空行和首尾换行。新旧附件都必须是桥附件目录内不超过 64MiB、非符号链接的普通文件，内容逐字节相同。缺少凭据、多附件、非普通文件、符号链接、文件内容变化或其他文字变化时继续拒绝。

上述核对通过后，原生消息和发给 Cursor 的文本均使用原先已核验的附件路径，再执行完整草稿、进程、模型和来源核验。路径归一不等于提交成功，不跳过标记移除前的完整验证，也不自动提交历史业务消息。原生队列仍按原请求摘要处理幂等性，不能用归一后的文本替换原请求身份。

验证应覆盖同内容附件的路径变化正例、原生与 ACP 两条入口，以及原生队列原请求摘要保持不变。拒绝条件应包括缺少或不匹配的恢复凭据、其他正文或换行变化、文件内容不同、缺失文件、符号链接、非普通文件和多附件包装。还应确认成功重试复用原草稿并仅提交一次，拒绝路径不粘贴、不清空、不发送 Enter，也不重写原消息或来源凭据。

分发版本与安装 skill 固定到 v0.1.11。安装器新增未修改的官方 v0.1.10 skill 两文件摘要识别：匹配时先保留完整备份，再原子更新；保留以前支持的官方版本，以及定制正文、元数据、额外文件和符号链接的拒绝覆盖行为。

打包前验证：Linux 完整 Node 测试 580/580 通过，无跳过；Python 安装器测试 31/31 通过。生产 RPC 测试覆盖附件重传、原生与来源正文一致、只提交一次、同客户端 ID 的旧失败轮次及队列重试和冲突。真实保留草稿与两份实际附件的只读恢复校验已通过，此项没有终端按键、正文编辑、提交或模型请求。

部署后的专用会话实发结果在对应 [Release 说明](https://github.com/KatarinaYuan/cursor-codex-bridge/releases/tag/v0.1.11) 中记录。只读恢复校验和版本固定不代表原业务消息已经发出；只有用户显式重试后才能确认该消息的实际提交。附件路径扫描保护见 [v0.1.10 验证说明](verification-v0.1.10.md)，来源绑定及 App 缓存边界见 [v0.1.9 验证说明](verification-v0.1.9.md)。

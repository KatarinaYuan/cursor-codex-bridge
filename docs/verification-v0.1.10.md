# v0.1.10 验证范围

本版修复多行草稿核验经过绝对附件路径时的一种误拒绝。Cursor 的已知斜杠补全菜单可能精确显示灰色 `No matches`，暂时遮住模型状态栏；这不表示草稿被修改，也不能单凭该提示认定所有菜单都安全。

放行范围仅限临时独占输入期间的只读光标扫描：光标必须位于预测的斜杠片段，菜单必须精确匹配，且草稿视口与已核验的原视口完全一致。方向键的作用须由已支持的 Cursor 输入行为确认，不修改正文、不按 Escape，也不发送 Enter 来关闭菜单。未知菜单、视口变化及消息末尾仍显示斜杠菜单时继续拒绝提交。

只读扫描完成后，桥必须回到草稿末尾，重新识别完整的原模型状态栏，再删除临时校验标记并发送唯一一次提交 Enter。正文、空行、首尾换行和原来源恢复凭据保持原样；核验失败仍保留未提交草稿，未知提交结果不得自动重发。诊断仅保留有界核验元数据，不加入完整消息或路径内容。

验证应覆盖已知斜杠菜单的精确识别、预期扫描位置与视口未变的正例，以及未知菜单、位置不符、视口变化、末尾菜单和模型状态栏未恢复时的拒绝条件。还需确认成功路径只有一次粘贴与一次提交、失败路径没有额外编辑或 Enter，临时租约和窗口设置仍按原规则恢复。

分发版本和安装 skill 固定到 v0.1.10。安装器新增未修改的官方 v0.1.9 skill 两文件摘要识别：匹配时先备份再原子更新；定制正文、元数据、额外文件或符号链接仍拒绝覆盖。保留之前已支持的官方版本。

打包前验证：Linux 完整 Node 测试 530/530 通过，无跳过；Python 安装器测试 31/31 通过。保留草稿的真实只读全扫描也已通过，包含绝对附件路径和补全菜单关闭延迟；此项没有粘贴、编辑、提交 Enter 或模型请求，结束后原历史和窗口均保持原样。部署后的专用测试会话实发结果在对应 [Release 说明](https://github.com/KatarinaYuan/cursor-codex-bridge/releases/tag/v0.1.10) 中记录；版本、安装或诊断通过不等于端到端成功。此前来源绑定与 App 缓存边界见 [v0.1.9 验证说明](verification-v0.1.9.md)，原文和换行保护见 [v0.1.8 验证说明](verification-v0.1.8.md)。

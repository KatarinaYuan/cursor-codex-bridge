# v0.1.14 验证范围

本版处理旧观察的稳定用户封套后来出现重复、正式历史已推进到后续请求，而原生聊天仍停在旧预览的特定情况。收尾依据来源、绑定和新捕获画面的组合证据；旧观察只记为已中断，不把失去归属的预览声明为成功完成。

## 恢复范围

新的后续请求边界适用于凭据有效的 `v1` 外部观察和 `v2` 原生已提交观察，需同时满足：

- 仍能核对原 Cursor 会话、工作目录、pane、进程及进程启动时间。`v2` 还需原客户端消息 ID、模型、原文摘要和来源消息映射一致。
- 原稳定来源 ID 已消失，同一封套摘要出现至少两个歧义显示条目；每个条目的原文与旧请求一致，且歧义组及其前缀均有明确完成记录。
- 最新来源是唯一稳定的用户封套，位于整个歧义组之后，时间戳严格更晚。不能仅凭正文相同、位置编号或终端末尾文字推断来源归属。
- 对同一原进程重新核对并捕获画面。来源尚有未完成尾部时，画面须精确对应最新请求的受支持忙碌状态，或结构完整的 `Clarifying Questions` 提问框；未知菜单、审批框或不匹配画面不能授权收尾。

完整来源已结束且新画面确认输入可用、任务空闲时，可按适用凭据收尾。此前 `v1` 外部观察的完整来源加空闲画面恢复路径继续保留。`v2` 缺少严格更晚的稳定边界时，不能仅凭空闲画面处理。

旧预览保留原生轮次、消息 ID、客户端消息 ID 和内容，状态改为已中断并说明来源归属丢失。歧义条目中的正式回复完整导入为独立历史卡片；没有明确完成证据的最新尾部不进入完成历史，也不发布其完成事件。后续观察使用该请求自己的稳定来源。

持久化的收尾凭据阻止以后扫描重新把来源归给旧预览。原生已提交请求以相同客户端消息 ID 和相同输入重试时，返回原已中断轮次；不同输入或无法核对的凭据被拒绝，不能因此再次提交。周期检查、桥重启、来源内容未变化时均需保持这一行为。

收尾和后续观察不向原 Cursor 输入、不重发模型请求、不改变模型、不重启 Agent，也不清空私人草稿。提问框识别只允许观察，不能自动回答、跳过提问或授予代发权限。

# v0.1.7 验证范围

此版本修复 Cursor 重写 transcript 后复用位置编号，以及运行时工具目录被误认为真人提问时的轮次归属问题。完整用户封套使用会话、时间戳原文和正文计算来源身份；只有完整且已识别的运行时目录作为当前请求的上下文。原 Cursor transcript 不作修改。

相同时间戳和正文重复时，该组来源降为歧义显示身份，不能建立提交归属；后续唯一来源仍可继续同步。无完整时间戳封套的旧记录保持兼容显示，不据此建立新的稳定提交恢复凭据。

Cursor 的时间戳精度为分钟。来源摘要不等同于原生事件 UUID；同一分钟内尚未完整导出的同文事件，只有在重复记录出现后才能识别为歧义。

已完成的隔离验证：

| 范围 | 结果 |
| --- | --- |
| 完整 Linux 测试套件 | 489/489 通过，零失败、零跳过；使用真实 Codex CLI、Node.js 22 和 tmux，隔离环境的辅助进程全部退出 |
| 来源解析与扫描 | 34 项通过；覆盖历史前缀变化、目录插入和移除、逐轮消息 ID、重复封套及后续唯一来源 |
| 用户正文 | 普通标签提及、目录片段、未知格式及用户封套内的目录仍保留为真人文本 |
| 隔离桥 RPC | 旧编号复用和目录注入后，原生旧轮次完成一次，后续真人请求独立保持运行；不发送终端按键、不启动 Cursor Agent |
| 提交与异步归属 | Enter 确认前不建立来源凭据；来源在异步持久化期间撤销时不使用过期快照完成；明确早于本次提交分钟的延迟旧导出不认领新消息 |
| 安装 skill 升级 | 45 项通过；识别官方 v0.1.6 完整文件哈希，保留旧目录备份，并拒绝覆盖定制内容 |

隔离测试不发送真实模型请求。真实服务切换、原生聊天状态和模型往返需另行验收；发布结果见 [v0.1.7 release notes](https://github.com/KatarinaYuan/cursor-codex-bridge/releases/tag/v0.1.7)。旧版已悬空且缺失来源凭据的轮次不能仅凭相同提示词或终端画面自动接管；普通安装器继续拒绝忙碌升级。

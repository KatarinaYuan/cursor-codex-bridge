# v0.1.4 验证范围

此版本修复桥接服务忽略 `thread/list` 的 `sectionId` 筛选，导致普通 Cursor 会话被当作置顶会话返回、无法正常参与原生 Recents 列表的问题。

分区语义为：未提供 `sectionId` 时返回所有符合其他筛选条件的会话；显式 `null` 只返回未分区会话；字符串只返回对应分区的会话。分区筛选与归档及其他现有筛选一起生效，不更改会话标识、历史、模型或活动时间。

真实部署的只读验证中，修复前置顶查询误返回 16 个 Cursor 会话，修复后返回 0 个；这批会话本身均未置顶。随后 Codex App 的原生会话列表在全局最多 50 条的查询中显示了 7 个 Cursor 会话，并成功通过原生会话读取接口读取已有历史。未进入这 50 条的较旧会话不能据此判断为丢失。

本次 Recents 验证未发送测试消息。它验证会话列表和已有历史读取；长时间闲置后的重连与长消息实发范围仍见 [v0.1.3 验证说明](verification-v0.1.3.md)。

发布前使用真实 Codex CLI 运行 `npm test -- --test-concurrency=2`：345 项测试通过，0 失败、0 跳过；另运行 `python3 -B installer/remote.test.py`，31 项通过。默认并发首次运行有两项模拟 Agent 初始化超时；对应文件单独运行 15 项通过，随后上述低并发完整运行全部通过，未修改超时或跳过测试。

回归覆盖分区筛选后分页、未分区旧记录、归档，以及未修改官方旧 skill 的备份升级、重复安装、dry-run、自定义内容和符号链接保护、替换失败回滚。安装 skill 通过系统校验；发布包另用隔离的 Codex 目录检查 CLI 版本、旧 skill 升级及 `npx -c` 的连续命令执行。该检查不连接开发机、不更改真实桥接服务，也不发送模型请求。

自动化使用虚构数据；真实账户、机器、SSH 别名、聊天内容、标题、数据库、窗口画面及会话标识均不随仓库或安装包发布。此处只记录脱敏后的验收范围；一次部署的验证不能替代其他环境的 App 端到端验收。
